### Solution Explanation

The problem requires us to find all occurrences of dictionary entries (words and phrases) within a sequence of tokens and annotate the tokens accordingly. This is a multi-pattern search problem with some specific complexities: case-insensitivity, tolerance for different separators, and handling of compound words formed by concatenating tokens.

My solution approaches this with two main components: an efficient dictionary index and a comprehensive search algorithm.

#### 1. Dictionary Index: The Trie

To enable fast lookups of dictionary entries, which can be single words or multi-word phrases, a **Trie** (prefix tree) is the ideal data structure.

*   **Normalization**: Before building the Trie, each dictionary key (e.g., `"black swan event"`) is normalized. This involves converting it to lowercase and splitting it into a sequence of "word parts" based on non-alphanumeric characters. For example, `"black swan-event"` becomes the tuple `('black', 'swan', 'event')`, and `"AAABBB"` becomes `('aaabbb',)`. This normalization makes the matching process insensitive to case and the specific separators used.
*   **Trie Structure**: The Trie is built from these normalized word parts. Each node in the Trie is a dictionary, mapping a word part to a child node. A special key (`_v`) in a node's dictionary stores a set of dictionary entry IDs, marking the end of one or more valid entries. This structure allows us to efficiently check if a sequence of word parts constitutes a valid dictionary entry.

The `build_dictionary_index` function handles this normalization and Trie construction.

#### 2. Annotation Algorithm: Breadth-First Search (BFS)

The `annotate` function performs the core logic of finding matches in the token sequence. A naive approach of checking every substring against every dictionary entry would be inefficient. Instead, I use a more systematic search.

The algorithm iterates through each token index `i` from `0` to `n-1`, treating each as a potential starting point for one or more matches. From each starting index, it performs a Breadth-First Search (BFS) to explore all possible ways that subsequent tokens can form dictionary entries.

A "state" in our BFS consists of `(current_trie_node, next_token_index, match_start_index)`. This represents an ongoing match attempt that has successfully traversed the Trie to `current_trie_node`, has consumed tokens up to `next_token_index - 1`, and was initiated at `match_start_index`.

From each state, the search explores two types of continuations:

1.  **Phrase-based match**: The algorithm scans forward from `next_token_index` to find the next word-like token. This token, treated as a single word part, is used to transition to the next node in the Trie. This handles phrases like `"black swan"`.
2.  **Compound-word match**: The algorithm attempts to form a longer word part by concatenating adjacent word-like tokens starting from `next_token_index`. This handles entries like `"blackswan"` being matched against tokens `["black", "swan"]`.

Whenever the search reaches a Trie node that marks a complete dictionary entry, the corresponding tokens in the original list are annotated. The `match_start_index` is used to determine the full span of tokens for the match, ensuring that inner separators are annotated but leading/trailing ones are not, as per the requirements. A `visited` set is used to prune the search space by avoiding redundant processing of the same state.

This BFS-based approach is robust, correctly handling simple words, compound words, phrases, and their overlapping and nested combinations in a single, unified process.

# Using a constant improves readability and maintainability.
_V_KEY = "_v"

def _normalize_key(key: str) -> tuple[str, ...]:
    """
    Normalizes a dictionary key into a tuple of lowercased word parts.
    It splits the key by non-alphanumeric characters.
    For example: "A black-swan event!" -> ("a", "black", "swan", "event")
    """
    parts = []
    current_part = []
    for char in key.lower():
        if char.isalnum():
            current_part.append(char)
        else:
            if current_part:
                parts.append("".join(current_part))
                current_part = []
    if current_part:
        parts.append("".join(current_part))
    return tuple(parts)

    """Checks if a token is word-like (non-empty and alphanumeric)."""
    # Note: isalnum() on an empty string is False.
    return token.isalnum()

def build_dictionary_index(dictionary: collections.abc.Mapping) -> object:
    """
    Build a normalized index from a dictionary for fast lookup of words and
    compound phrases.

    The index is a Trie data structure where each node is a dictionary.
    Edges are labeled with normalized word parts. Nodes corresponding to the
    end of a dictionary entry store the entry's value.

    Parameters:
        dictionary: Mapping strings (keys) to meanings (values).
    """
    trie_root = {}
    for key, value in dictionary.items():
        parts = _normalize_key(key)
        if not parts:
            continue

        node = trie_root
        for part in parts:
            # Python's dict.setdefault is a concise way to get a key's value
            # or insert it with a default if it doesn't exist.
            node = node.setdefault(part, {})

        # Store the dictionary value at the terminal node.
        # A set is used to handle cases where different dictionary keys
        # normalize to the same sequence of parts.
        node.setdefault(_V_KEY, set()).add(value)

    return trie_root

    1. Phrases: Sequences of word-like tokens separated by non-word-like tokens.
    2. Compound words: Sequences of adjacent word-like tokens concatenated.
